# motui 1.1.7 — the audit sweep

**A sealed block is frozen content, not frozen state.** The 1.1.6 audit found
that several components' row caches could serve a frame older than their live
inputs. `Dialog`'s snapshot now carries everything its render reads — `title`,
`width`, `frame`, `shade`, `align`, the border tuple, the resolved bands and
the body (through the body's own `revision()` when it has one) — so a frame
parameter changed in place after the block was sealed reaches the screen.
`Diff`, `Tabs`, `NavList`, `Slider`, `ProgressBar` and `Collapsible` implement
`Revisioned` for the first time, completing the render-cost rollout: a hover, a
focus flip, a selection or a value assignment on a sealed block now misses the
cache and repaints. Each fix landed with a reproduction that was red first —
twenty-four of them — and the sealed-block tests compare `block.rows(width)`
against a direct `render(width)` row by row.

**The lifecycle verbs close.** `Palette` gains `detach()`, delegating its
modal's unmount exactly as the eight sibling controllers do; it is idempotent
and distinct from `close()`, which only hides. A detached `Find` is inert:
`handle()` answers `False` to every key instead of continuing to consume input
after unmount. The gesture scroll path drops a redundant direct `invalidate()`
beside `set_selection`, so one scroll extension is exactly one repaint.

**Small truths.** The source-checkout `__version__` fallback now names the
release it is cut from (1.1.7) and a test pins it to `pyproject.toml`. The
documentation matches the code again: the root facade's 34 names are complete
in `DESIGN.md`, `COMPONENTS.md` points at the authoritative `__all__` instead
of a list `README.md` never had, three decision references resolve to the
specs that define them, and "styles resolve once at construction" is now
backed by a test.

**Breaking — `motui.kernel.MORE_BELOW` is removed.** The kernel no longer
paints the `─ more below ─` marker row. A scrolled window shows the content
rows themselves, blank-padded below the content, so every painted row is
either a real block row or empty fill. The marker was the one visual in the
core that bypassed the theme system, it silently took a content row, it
duplicated the host's chrome whenever a `Scrollbar` was mounted (the demo
mounted one), and its ownership table pointed at the block it covered rather
than the block it showed — a click on the marker dispatched to an invisible
block. Scrolling feedback belongs to the host's chrome; a host that wants it
mounts `Scrollbar`. Removing the marker closes the hit-test mismatch
structurally. This is a documented clean cut, no shim, shipped as a PATCH
under the year-let rule.

**Gates.** 1570 tests pass (31 new), the eleven golden pages match, both demo
paths exit 0, and the framebench render-hash moved by design:
`de48e747…` → `f872187a…` — three pages' last window row now shows the
content row the marker covered. The hover/click probe agrees across all 1740
cells of the interactive components.
