# motui 1.2.1 — ownership and whitespace

**A PATCH for two places where structural state disagreed with the text a
user typed or the document a block belongs to.**

## Editable text keeps every character

`Input` and `Editor` wrapped their visual rows with the prose break rule,
which drops leading, trailing and break whitespace. A typed space therefore
never reached a rendered row: the buffer changed, the row did not, and the
painter correctly emitted no bytes until the next visible character.

`core.text.wrap_spans` now has an explicit editing mode
(`preserve_whitespace=True`): contiguous spans that reassemble the exact
text, word-aware, with the same wide-cell rule. `TextBuffer` uses it. The
prose path (`wrap_text`, `wrap_line`, Markdown, tables) is unchanged, so no
golden frame moves.

## Content ownership is not input focus

`TUI.add` and `TUI.system` used to append to the focused pane when `pane=`
was omitted. Focus is transient input state; a long-lived producer that
mounted a block after the user clicked another pane wrote into that pane's
document, and closing a sidebar took the output with it.

With no `pane=` they now target the main document — `primary`, or the first
content pane in paint order. `TUI.split` keeps targeting the focused pane,
because it is a user structural action. `TUI.reveal(bid, row)` now resolves
the pane that holds the block id, so it can reveal a block in a non-focused
pane.

## Migration

```python
# before: implicitly the focused pane
tui.add(widget)

# after: opt in explicitly where that is still the intent
tui.add(widget, pane=tui.frame.focused_pane)
```
