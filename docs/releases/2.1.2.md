# motui 2.1.2 — one widget vocabulary

**2.1.2 is a consistency release, not a feature release.** The component
library was built family by family: constructors took their content in
different positions, the same cursor concept was called `index` here and
`selected` there, `take()` answered a bool for one control and an index for
another, and each family carried its own key table and style merge. 2.1.2
makes one contract across all widgets and removes the old spellings. It is
the one deliberate breaking widget pass inside 2.x; after it, the additive
rule resumes.

The complete old-to-new table is in
[MIGRATION](https://github.com/Shingwha/motui/blob/v2.1.2/docs/MIGRATION.md).
This page explains the shape of the change.

## Constructors

The primary content is the one positional argument; configuration is
keyword-only. The style tail runs `glyphs, theme, styles, keymap`.

```python
Tabs(items, *, index=0, ...)
Table(rows, *, headers=(), ...)
Tree(nodes, *, indent=2, ...)
Dialog(body, *, title="", buttons=(), ...)
Collapsible(body, *, title="", open=True, ...)
Canvas(*, width=20, height=8, plot_marker="cell", ...)
PixelCanvas(*, width=20, height=8, palette=None, ...)
ProgressBar(value, *, maximum=1.0, ...)
```

`PixelCanvas(palette=None)` now derives an eight-slot palette from the
widget's theme; an explicit palette still wins. `Canvas.marker` became
`plot_marker` because it only affects `plot()`.

## State

One name per concept:

| Concept | Name |
|---|---|
| cursor position | `index` (int, 0 for an empty collection) |
| item under the cursor | `selected` (the item or `None`) |
| multi-selection | `marked` (`MarkSet` of source indices) |
| scalar value | `value` |
| boolean toggle | `checked` |
| fold/dropdown | `open` |
| text | `text` |

`TreeNode.expanded` became `open`; `ComboBox.is_open` plus `open()` and
`close()` became the `open` property plus `toggle()`; `Table.index` is an
int and `Table.selected` is the row; `ProgressBar.fraction` is a read-only
derivation of `value / maximum`.

## Verbs and results

The shared verbs are `activate()`, `toggle()`, `select(index)`,
`move(delta)`, `advance()` and `take()`. `on_action` routes exactly nine
names: `prev`, `next`, `first`, `last`, `page_prev`, `page_next`,
`activate`, `toggle`, `open`, `close`. Movement and selection clear a
pending result; only activation and toggling write one. `take()` reads once
and clears; a legal `None` result is kept distinct internally from "nothing
pending".

The result shape follows the family: a button answers `True`, a checkbox
its new state, a select its option value, a table its activated row, a tree
its node, tabs and menu bars their label, a form its submitted dict, a
dialog its button value.

## Keymaps and activation

`CURSOR_KEYMAP` is the one cursor table: up/left = prev, down/right = next,
home = first, end = last, page_up/down = page_prev/page_next. The tree
replaces left/right with close/open. Enter and space activation is the focus
layer's fallback; components no longer bind `enter` themselves. Text fields
keep their own `TextBuffer` key table.

## Styles

Style is still role-based, not per-component. `SurfaceStyles` gained
`control`, `accent`, `danger` and `inactive`; `ControlStyles` is now a
state overlay -- `hover`, `focus`, `active`, `disabled` and `overlay()` --
instead of a base band plus `band()`. `ButtonKind` gives one control four
roles:

```python
Button("save", kind=ButtonKind.PRIMARY)
ButtonSpec("delete", value="delete", kind=ButtonKind.DANGER)
```

Input and Editor rows sit on the `surfaces.control` field floor; Link,
Tabs and MenuBar focus is visible; Dialog interiors use `surfaces.raised`.
`Theme.flat()` maps every new surface to `NONE` and the control states to
underline/bold/reverse/dim, so a no-background theme stays legible.

## Composition and drawing

`Line.overlay` and `Surface.overlay` compose transparent cell layers:
a plain unstyled space shows the layer below, any other cell wins and
merges the base style. `Stack` paints children bottom to top; its hits
prefer the first interactive layer, so a background canvas is not a click
target. `Align` places one child at a two-dimensional anchor.

`Drawing` is the shared lifecycle behind `Canvas` and `PixelCanvas`:
sizing is explicit (`resize` or `fit`), `surface()` caches the image, and
`render()` only clips. A render at another width can no longer drop a
board's ink.

## Documentation and tests

Widget and kernel docstrings were rewritten as contract cards and reduced
from 13,004 to 3,787 lines. `CONTRACT`, `WIDGETS`, `ARCHITECTURE` and the
README describe the new API; ADR-027..030 record transparent composition,
the drawing lifecycle, the state/verb/result contract and control styling.

The suite was consolidated from 1,838 collected cases to 1,382 by removing
repeated capability, keymap and height-budget matrices; the unique
editing, table, tree, scroll, Markdown, Diff, syntax and pixel coverage is
unchanged. The nine semantic frames stay green, and the public surface is
244 rows.

The ruff ratchet is gone: widgets, app and tests are checked without
directory excludes. Only generated Unicode ranges, frozen `Style` defaults,
the immutable `selection` default and the framebench bootstrap keep narrow
per-file ignores.

## Migration

Read
[MIGRATION §3](https://github.com/Shingwha/motui/blob/v2.1.2/docs/MIGRATION.md)
for the full 2.1.0 -> 2.1.2 table and checklist. The short version: move the
primary content to the first position, rename the state, call the verb, and
read the result. There are no aliases.

## Release facts

- Version: **2.1.2** (released 2026-10-29).
- Public surface: 244 rows across seven facades; `motui.widgets` has 51

- Tests: 1,382 passed; nine semantic goldens; `ruff`, `pyright`,

- The release was prepared and tagged locally; no push or publish is
