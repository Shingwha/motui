# motui 2.1.0 — PixelCanvas, and a showcase that shows it off

**2.1's headline is a new widget and a demo rebuilt around it.** The new
sub-cell `PixelCanvas` draws braille and half-block art through a small
palette/heat engine; the showcase no longer just lists components — it
paints with them, explains them, and helps you drive them. The engine
extraction, test cleanup and performance work are supporting changes.

## PixelCanvas

`PixelCanvas` is a `Widget` that owns two private `motui.pixel.Raster`
layers:

- **art** — lines, sprites and rings at the marker resolution;
- **fill** — half-block blocks behind the art.

Every cell is a 2x4 sub-cell grid. Drawing verbs take sub-cell positions on
one layer:

```python
from motui.kernel.layout import Constraints
from motui.pixel import Marker, PixelPalette
from motui.widgets import LayerName, PixelCanvas

palette = PixelPalette(
    slots={1: ((255, 99, 132), (122, 46, 64))},
    bg=None,
)
canvas = PixelCanvas(20, 8, marker=Marker.BRAILLE, palette=palette)
canvas.disc(20, 16, 5, 1, layer=LayerName.FILL)
canvas.ring(20, 16, 12, 2, 1)
canvas.decay(40)                      # cool the trail
surface = canvas.render(Constraints(width=20, max_height=8))
```

The verbs are `plot`, `erase`, `stamp`, `line`, `rect`, `disc`, `ring`,
`clear` and `decay`; `heat` is a keyword (`0..255`) and `layer` selects
`ART` or `FILL`. `marker` is a validated `Marker` (`BRAILLE` or `HALF`),
`pixel_width`/`pixel_height` answer the sub-cell geometry, and `resize` /
a new render size rebuilds the rasters empty — pixel scenes redraw each
tick, so that is the contract.

The engine is `motui.pixel`: `Raster` (private slot/heat grids, `at()` as
the one read door), `PixelPalette` (main/cool colors plus optional
background), `Marker`, `PixelLayer` and `quantize`. The last one turns
layered rasters into ordinary kernel `Line`s. The pixel surface is
**new in 2.1 and provisional**; see [CONTRIBUTING](../../CONTRIBUTING.md).

Where it is used:

- `splash` — the 5x7 letterforms are stamped onto the fill layer; the
  starfield and neon sweep ride the art layer.
- `motion` — braille rings shrink onto half-block target discs, and bursts
  and misses fade through explicit heat.
- `PixelCanvas` is the only public door to `quantize`; the widget's render
  is the layer order (art wins a cell both claim).

## The showcase

`python -m motui` is one interactive page over ten scenes. The shell opens
on the splash, then the Home tiles:

| Scene | What it shows |
|---|---|
| `components` | real widgets beside the code that built them; modal, toast, sort |
| `layout` | split, dock, two scrolls and a wide table; a visible drill strip |
| `motion` | the pixel rings game; braille rings, half-block targets, heat fade |
| `dashboard` | a streaming window derived only from the tick number |
| `terminal` | SGR/DECSET, the marker ladder and a live mouse feed |
| `themes` | one sample re-skinned by four themes; `c` compares them |
| `snake` | the standalone Canvas game |
| `gallery` | a real page assembled from the widget library |
| `splash` | the 5x7 pixel wordmark and its four style packs |
| `menu` | the Home tile grid |

The scene registry is one value (`SceneSpec`: name, title, blurb, factory,
keys, miniature, preview phase). It drives `SCENES`, the Home tiles, the
command palette and the semantic snapshots. `Scene.enter()` is the one
reset door; the shell calls it on every switch and on a seek rewind; a
wipe holds the outgoing scene at the phase it was left on. Motion's preview
phase is 96, so its page, headless frame and golden are alive.

Home now reaches Snake (`s`) and Gallery (`g`), the command palette
(`ctrl+p`) reaches every jumpable scene, and `F1` opens a help panel that
lists the current scene's keys and pauses the clock. `--list`,
`--version`, `--pages` and two headless sizes are part of the entry
surface.

## Under the hood

- The pixel engine moved out of the kernel into `motui.pixel` before the
  release; the kernel is pure values and protocols again.
- The demo is split into `cli`, `preview`, `commands`, `scene`,
  `registry`, `common`, `minis`, `shell` and `sections`; splash and motion
  are packages; `demo/showcase.py` and `demo/art.py` are gone.
- Tests mirror the tree (`tests/pixel`, `tests/demo`); timing lives in
  `tools/framebench.py`; cross-widget contracts are parameterized once;
  ten semantic goldens are recorded at each scene's preview phase.
- `framebench` adds `pixel-quantize`, `scene-render` and `scene-paint`
  (p50/p95). The 100x30 paint p95 stays under the 8 ms budget.
