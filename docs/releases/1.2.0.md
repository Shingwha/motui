# motui 1.2.0 — convergence

**Three layers, one owner per state.** 1.2.0 is the API-convergence release:
the kernel/keys/interaction/commands namespaces collapse into `core`,
`widgets` and `app`; the high-level `App` owns the default interaction
policy; every themed component shares one `Widget`/`Styles` seam; viewport,
ScrollView and scrollbar share one `ScrollState`; and every list-like widget
shares one `Cursor`.

**App is the entry point.** `App` mounts focus, pointer, selection, wheel
and page routing, toasts, tooltip, find and the command palette, and runs
the documented dispatch order. `TUI` stays available as the low-level
driver: its `read_event()` is now a pure read, with no hidden scroll or
focus side effects. A host that wants its own loop can still drive it
directly.

**Widget and Styles replace the constructor sprawl.** Every themed component
accepts `theme=` plus one `styles: Styles` value instead of per-token
`style=` / `hover_style=` / `focus_style=` / `disabled_style=` arguments.
Styles resolve at render time, so assigning `App.theme` repaints mounted
widgets without rebuilding them.

**One state, one owner.** `ScrollState` drives Viewport, ScrollView and the
pane Scrollbar; `Cursor` drives the data views, menus and strips.
`BlockState`/`seal`, `Delegate`, the `Host` seam, the widget factories and
the capability-protocol facade exports are gone. `Select` is single-choice;
`MultiSelect` is the marked variant.

**Interaction fixes that were structural, not cosmetic.**

- `ScrollView(bar=True)` now owns a real bar: the thumb drags, the track
  pages and the wheel reaches it. `App` routes press/motion/release through
  a general `drag` verb before the gesture and pointer tiers.
- `Table(wrap=True)` wraps long cells to their column budgets instead of
  ellipsizing them; Markdown tables inherit the same engine. `wrap=False`
  keeps the old truncation.
- Compound widgets declare `owns_focus`; `Form` and `ComboBox` keep their
  fields out of the App's focus ring and route their keys themselves. A
  click is split into the leaf's action and the ancestors' `focus_at`, so
  clicking a form's second field moves the form cursor and the next
  keystroke lands there. A container is never activated by a click on its
  background.

## Breaking changes

- `motui.kernel`, `motui.keys`, `motui.interaction` and `motui.commands`
  are removed. Import from `motui.core`, `motui.widgets` or `motui.app`.
- `App` is new; `TUI.read_event()` no longer absorbs wheel/page or applies a
  focus policy. `TUI.add` returns the block id; `get`/`remove` return the
  component; `dock` takes a component.
- Widget constructors no longer accept `*_style` or `focused=`. Pass
  `styles=Styles(...)` and set `widget.focused` (or use `App.focus`).
- `Select(multi=..., marked=...)` is `MultiSelect(...)`.
- `ScrollView(scrollbar=...)` is `ScrollView(bar=...)`.
- `CommandPalette` and `ColorPalette` are distinct names; `app.app.App` is
  `app.application.App` (public import: `from motui.app import App`).
- The root is a curated 41-name face; the complete library remains at
  `motui.widgets`.

## Migration sketch

```python
from dataclasses import replace
from motui import App, Input, Text, Theme, Styles
from motui.widgets import Form, Field, ScrollView

# 1.x manual loop -> 1.2 App
class Greeting(App):
    def on_start(self):
        self.name = Input(placeholder="your name")
        self.add(self.name, id="name")
        self.focus(self.name)
        self.bind("enter", self.greet)
        self.bind("c-c", self.quit)

    def greet(self):
        self.add(Text(f"hello, {self.name.text or 'world'}"))

# style=... -> styles=Styles(...)
button_styles = Styles(controls=replace(Theme().controls, base=...))
```
