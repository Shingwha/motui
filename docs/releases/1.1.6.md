# motui 1.1.6 — the borderless switch

**New — `frame=False` on `Panel` and `Dialog`.** The frame is decor, not
structure, so the box can drop and the layout stay. A borderless `Panel`
renders its child inset one column per side with every row still spanning the
panel's width, and an explicit `style` becomes the panel's **ground**: the
panel's own cells fill with it and it merges *under* the child's segments —
the child's colors win, the ground shows wherever it has none (the `Padding`
`fill_style` rule) — so an inset band needs no `Padding`/`Panel` swap. A
borderless `Dialog` is the body and the button row with no frame rows: the
body stays one pad column in, `align`, the cursor and the click mapping are
unchanged (the hit columns shift with the missing border), `border` and
`border_style` are accepted and unused, and the `danger` cue rides the
dangerous button's own `error` band.

**The title goes with the frame, in both.** There is no edge left to embed it
in, so the host composes its own heading — the Rich reading of a box-less
panel. The switch is spelled `frame=False` rather than a `border=None` value
because `None` already means "the default box" on `Dialog.border`; borderless,
the theme's `border` field is never consulted (a themed ground would repaint
the child's own unstyled runs), and below the padding's minimum width the bare
child keeps the width, the frame's own degradation.

**Additive and default-preserving.** Framed rendering is byte-for-byte what
1.1.5 rendered — every demo page and the whole pinned surface hold — and
`confirm_dialog` / `prompt_dialog` forward the switch. The demo gains a
`panel · frame off` exhibit and a "no frame" dialog trigger, and the in-app
manual names the switch.
