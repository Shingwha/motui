# motui 1.2.2 — the frame's cost, and a security door

**A PATCH with two stories: the steady-state frame stops paying for the
whole document, and rendered content can no longer carry terminal
commands.**

## Content can no longer inject terminal control sequences

A tool output, a model reply or a file content that contains an escape
sequence used to reach the terminal verbatim: `ESC[?1000l` switched mouse
reporting off until the app was restarted, `OSC 52` could write the
clipboard, `OSC 0` could retitle the window. The mode was asserted once at
startup and nothing re-asserted it, so one injected frame killed the mouse
while the keyboard kept working.

`Segment` construction is now the one door between content and terminal
commands. `text` and `link` are sanitized to display cells only: C0, DEL
and the C1 range are deleted, and a tab normalizes to one space — the
repo's only tab rule, now applied to directly-built segments too. The
escape bytes disappear; what remains (`[?1000l`) is inert, visible text the
width model already accounts for. Clean text renders byte-for-byte
identically (the golden set and the framebench digest prove it), and every
escape the toolkit emits is still constructed in `motui.core.ansi`, as its
module constitution always claimed. There is no opt-out: text that must
carry color belongs in a future ANSI-parsing component, not a passthrough.

## The steady frame stops paying for the whole document

Every layout used to walk every block of the document, copying each block's
cached rows to hand them out. A long session paid that per frame even when
nothing changed and the window sat thousands of rows away from the tail.

`Viewport.layout` now keeps a private body index keyed on the document's
mutation count and the width: a frame probes each block's revision snapshot
(equal snapshot proves equal rows), re-measures only the blocks that moved,
maintains the prefix sums from the dirtiest entry, and locates the window
by binary search. Two read-only doors beside `Block.rows()` —
`rows_view()` (the cached rows, borrowed, no copy) and `row_count()` (the
count alone) — serve the internal walkers, and `Document.blocks()` caches
its snapshot tuple behind the new public `Document.mutation` counter.
`Frame.compose` reuses its plan and table buffers between compositions and
uses a single full-width write as-is, and `TextBuffer.value` caches its
join under `version` so a host reading the text every keystroke pays O(1)
between edits.

Measured on the framebench workloads: a 3000-row document's scroll notch
drops from ~1.6 to ~0.8 ms, the new `idle-long` line (a zero-change
steady frame over 3000 rows) reads ~0.6 ms, and the render digest is
unchanged — same bytes, less computation.

## Migration

None required. The new names (`Document.mutation`,
`Block.rows_view`/`row_count`) are additive doors, documented in the
changelog; hosts that fed control characters through content will see them
disappear from the output (that is the fix); a tab inside directly-built
segments now renders as one space, the same rule the wrap path always had.

## Gates

- 913 tests pass (893 at 1.2.1 plus 20 new across the two groups); the
  existing tests are unmodified.
- The golden topics and the framebench render digest are byte-for-byte
  unchanged.
- End-to-end: a document carrying `ESC[?1000l`, `OSC 52` and `OSC 0`
  payloads paints none of them.
