# ADR-026 · Tests pin contracts, not implementation

- **Status:** Accepted (2.1)
- **Context:** The suite grew to 1660 cases and 1335 functions. Many were
  valuable width/mode matrices, but some duplicated a cross-widget
  contract, asserted private fields, timed a component in a unit test, or
  repeated a semantic golden as text.
- **Decision:** A test names a public contract or a real regression.
  Visual details belong to the ten semantic goldens; timing belongs to
  `tools/framebench.py`; a cross-widget contract lives once in a
  parameterized `test_contracts.py`; a scene test asserts public state, not
  `scene._field`. The demo suite mirrors `tests/demo`, the engine
  `tests/pixel`.
- **Why:** Test count is a proxy. The cost is maintenance when one behavior
  is pinned in five files or one private field; deleting boundary matrices
  to hit a number would lose real coverage. One contract, one place, makes
  a failing test point at the behavior that broke.
- **Consequences:** New tests must justify their level. `CONTRIBUTING`
  allows the cross-widget contract file as the one exception to
  "one source module, one test file". A UI change re-records goldens
  instead of editing five string assertions. Performance regressions are
  read from framebench, not from flaky unit assertions.
- **Alternatives:** Delete by percentage (rejected: loses boundaries);
  keep implementation tests and mock the internals (rejected: tests the
  mock); move every render check into goldens (rejected: component-level
  failures would lose their focused assertion).
