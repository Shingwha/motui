# ADR-015 · Terminal metrics stay out of Constraints

- **Status:** Accepted (2.0)
- **Context:** Images and pixel-based media need cell metrics. The tempting
  move is to put a render environment, including terminal capabilities,
  into `Constraints` now so every future component can reach it.
- **Decision:** Do not add terminal metrics or a `RenderEnv` to
  `Constraints`. Pass a capability value or a collaborator to the component
  that needs it. Reconsider only when a third independent consumer exists.
- **Why:** The kernel stays pure and a component test needs no fake
  terminal. A speculative environment field would become a contract before
  any media pipeline is designed.
- **Consequences:** 2.0 has no `RenderEnv` and no image protocol. A future
  media seam injects its renderer at the terminal boundary instead of
  changing the component protocol.
- **Alternatives:** Add `Constraints.env` now (rejected: speculative and
  hard to shrink); pass a global (rejected: hidden state and no test
  isolation).
