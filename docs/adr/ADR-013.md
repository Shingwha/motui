# ADR-013 · Scroll is a 2D value; horizontal windows ship in 2.0

- **Status:** Accepted (2.0)
- **Context:** The 1.x scroll state was one integer offset. A 200-column
  table was unreadable because the only way to see later columns was to
  truncate. The shape of the future API mattered now, even if the full
  document-flow case could wait.
- **Decision:** `Scroll` is a two-axis value (`x: ScrollAxis`, `y:
  ScrollAxis`); `ScrollAxis` carries offset, content, viewport, `sticky`,
  `clamp`, `reveal` and `thumb`. Horizontal scrolling in 2.0 is limited to
  non-wrapping content inside `ScrollPanel(axis="x"` or `"both")`.
- **Why:** The value shape is correct now, and horizontal windows cover
  the real cases: wide tables, wide code and fixed-grid charts. A
  document-flow horizontal scroll would require every section to have a
  meaningful column model.
- **Consequences:** Panes still scroll vertically only. `ScrollPanel` owns
  horizontal movement and hard-cuts columns (the removed columns are
  scrollable, so an ellipsis would lie). `ScrollState` remains the mutable
  geometry behind the panel and pane chrome in this release; a full
  replacement is post-2.0.
- **Alternatives:** Keep a 1D state and change later (rejected: every
  formula and stored anchor would move); horizontal document flow in 2.0
  (rejected: too large and semantically unclear).
