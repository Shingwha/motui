# ADR-010 · The performance ceiling is 30 fps

- **Status:** Accepted (2.0)
- **Context:** Python object work plus terminal bandwidth set a hard
  practical limit on full-screen repaints. Chasing 60 fps would push
  optimization into the architecture and make the value model pay for a
  target most terminals and hosts cannot use.
- **Decision:** The design target is up to 30 full-screen frames per
  second. Do not optimize for 60 fps full-screen cell-by-cell painting.
  Document the limit and expose `throttle` and animation rate knobs.
- **Why:** A reachable target keeps the architecture honest: pure values,
  per-section caches, per-row diffs and batched writes are enough. A
  faster target would encourage hidden mutable state.
- **Consequences:** `framebench.py` tracks frame costs and `App.every` /
  `App.animation` let a host choose its rate. The library does not promise
  60 fps; workloads that need it are out of scope.
- **Alternatives:** Chase 60 fps full-screen (rejected: unreachable in
  Python without compromising the model).
