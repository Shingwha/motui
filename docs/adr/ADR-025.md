# ADR-025 · Scene entry is the one reset door

- **Status:** Accepted (2.1)
- **Context:** The 2.0 demo let scenes infer a re-entry from a backwards
  phase jump, with `_MAX_SYNC` caps and three slightly different rewind
  branches. The wipe also rendered the old scene at the new phase, so it
  was not the frame the user left.
- **Decision:** `Scene.enter()` resets every scene. `Showcase` calls it for
  the initial scene and on every switch; `seek()` calls it on a rewind.
  Within one entry the phase passed to `tick()`/`render()` is
  non-decreasing. A wipe records the old scene's phase and renders the old
  scene at that frozen phase. A resize that changes the motion board starts
  a fresh game.
- **Why:** State has one owner and one reset point. The shell no longer
  guesses from a phase delta, the wipe shows the actual outgoing frame, and
  headless seeks are explicit rather than incidental. It removes three
  copies of the most error-prone code in the demo.
- **Consequences:** Direct callers of a scene must call `enter()` before a
  fresh timeline and must not render backwards without a seek. Tests that
  drive a scene directly use monotonic phases; shell tests exercise
  re-entry. Scene state that tests need is public, not private.
- **Alternatives:** Keep per-scene rewinds (rejected: ghosts and duplicated
  caps); reset the whole shell on every render (rejected: destroys
  animation state); render the old scene at the new phase (rejected: the
  wipe lies).
