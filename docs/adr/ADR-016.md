# ADR-016 · Values own behavior

- **Status:** Accepted (2.0)
- **Context:** Row, selection, mark and scroll operations were free
  functions (`fit`, `fill`, `fuse`, `overlay`, `rest`, `cut_line`,
  `slice_line`, `action_at`, `highlight`, `extract`, `mark_prefix`, ...).
  The same concept had several entry points, and discoverability was poor.
- **Decision:** Values own their operations: `Line.clip/reflow/pad/fill/
  merge_span`, `Selection` with the `highlight`/`extract` functions,
  `ScrollAxis.clamp/reveal/thumb`, `Scroll.with_x/with_y`, `MarkSet`, and
  `Hit` leaf views. Module-level helpers remain only for construction and
  measurement (`text.*`, `Line.from_text`, `Surface.of`).
- **Why:** Operations are discoverable on the value, chainable, and testable
  against a value with no surrounding object. The number of scattered
  free functions shrinks.
- **Consequences:** The old free functions are removed from the
  application surface; `fuse`/`overlay`/`rest` remain private helpers
  inside `motui.kernel.cell`. The module-level functions that stay public
  are construction and measurement helpers (`cut_line`, `slice_line`,
  `wrap_line`, `action_at`, `visible_width`, `text.*`), not a second
  vocabulary for the same row operations.
- **Alternatives:** Keep the free-function vocabulary (rejected: duplicate
  doors and poor discoverability).
