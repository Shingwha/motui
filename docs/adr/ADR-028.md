# ADR-028 · Drawing sizes explicitly and renders purely

- **Status:** Accepted (2.1.2)
- **Context:** `PixelCanvas` used to sync its rasters to the render
  constraint, so rendering the same board at a probe width rebuilt it
  empty. `Canvas` and `PixelCanvas` each carried their own width, height
  and surface cache, and a drawing verb had no single invalidation door.
  The invariant matrix renders every component at several widths, which
  made "render follows constraints" a data-loss bug rather than a
  convenience.
- **Decision:** `Drawing` is the shared internal base of `Canvas` and
  `PixelCanvas`. `width` and `height` are cell dimensions; assigning either
  one calls `resize(width, height)`. `resize` clamps at zero and is a no-op
  when the size is unchanged, so a redraw loop does not lose ink between
  equal constraints. `fit(c)` adopts `c.width` and `c.max_height` (a
  natural constraint keeps the current height). `surface()` answers one
  full-size cached `Surface`. `render(c)` clips that image to the
  constraints and never resizes. Subclasses supply `_resize_storage`,
  `_build_surface` and `_invalidate`; every drawing verb calls the last one.
  `Canvas` becomes keyword-only (`plot_marker`, no `styles`);
  `PixelCanvas` becomes keyword-only and derives `PixelPalette.from_theme`
  when `palette=None`.
- **Why:** Sizing is a host decision, not a side effect of a probe.
  Rendering stays pure and repeatable at any width, the invariant matrix
  cannot destroy a game board, and one cache serves both widgets. A real
  resize rebuilding the pixel rasters empty is acceptable because a pixel
  scene redraws on every tick.
- **Consequences:** A host that follows a changing slot must call `resize`
  or `fit` before paint. `render` clips, never scales, so a smaller probe
  shows less of the image rather than a shrunken one. Assigning a new width
  to a `PixelCanvas` drops its ink; `Canvas` preserves the overlapping
  cells. Negative sizes clamp rather than raise.
- **Alternatives:** Resize inside `render` (rejected: order-dependent and
  lossy); rescale the image to the constraint (rejected: expensive and
  blurry); keep per-widget caches (rejected: two invalidation rules);
  introduce a measure phase (rejected: ADR-002).
