# ADR-002 · No measure/render split

- **Status:** Accepted (2.0)
- **Context:** A host needs to fill the remaining height of a pane. The
  obvious alternative is a measure pass followed by a render pass, but that
  makes every component implement its layout logic twice.
- **Decision:** One pass: `render(Constraints)` plus `Sizing.FILL`. A
  document holds at most one `FILL` section, placed after every natural
  flow section; containers allocate the remaining height to it.
- **Why:** One implementation per component covers games (one fill), IDEs
  (fixed sidebars plus a fill) and chat (a scrolling list plus a fixed
  composer).
- **Consequences:** `Document.add` validates the fill rules: at most one,
  only in the flow, and nothing may follow it. `App.fill(component)` is the
  pane-level convenience.
- **Alternatives:** A measure/render two-phase protocol (high cost, doubled
  API surface, two chances to disagree).
