# ADR-018 · TerminalOptions and MouseMode

- **Status:** Accepted (2.0)
- **Context:** Terminal switches were spread across `App`, the low-level
  driver and `Screen`: `mouse=True`, `hover=True`, `color_mode=`,
  `focus_events=`, `sync=` and `keys=`. `hover` was not an independent
  feature; it was all-motion mouse reporting.
- **Decision:** `TerminalOptions` is the one terminal configuration:
  `stream`, `input`, `mouse`, `paste`, `focus_events`, `color_mode`,
  `sync`, `screen`. `MouseMode` has exactly `OFF`, `BUTTON`, `DRAG` and
  `MOVE`. `App(terminal=TerminalOptions(...))` is the recommended form.
- **Why:** A new switch changes one type and one mapping. The 1000/1002/
  1003 terminal modes are explicit, and hover stops pretending to be a
  separate boolean.
- **Consequences:** `App` keeps the legacy switches only as a compatibility
  fold into `TerminalOptions`; a supplied `terminal=` wins. Screen
  construction maps `MouseMode` to its mouse/hover switches once.
- **Alternatives:** Keep `mouse` + `hover` (rejected: ambiguous and
  duplicated); put the switches on `Screen` only (rejected: the input
  source and paste/focus behavior are not screen properties).
