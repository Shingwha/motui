# ADR-007 · Dispatch order is data

- **Status:** Accepted (2.0)
- **Context:** The 1.x `App.dispatch` was a ten-branch `if` chain. The
  order was real policy, but it was neither visible as a list nor
  replaceable without editing the class.
- **Decision:** Each interaction tier answers only "did I consume this?".
  `App.dispatch` walks the documented order: palette, modal, find, toasts,
  mounted controllers, wheel, mouse, focused widget, page keys, bindings,
  tab, host hooks. `auto=False` mounts no default tiers.
- **Why:** The order is visible, testable and replaceable. A new tier does
  not require editing an ever-growing chain, and a host can keep the
  default policy or mount its own.
- **Consequences:** The order is a public contract; changing it is an
  architecture review. A `ResizeEvent` is broadcast to every widget before
  the chain and is never consumed by the broadcast.
- **Alternatives:** Inherit and call `super().dispatch` (1.x, rejected);
  move dispatch into a controller registered in the chain (adds a layer
  without removing the ordering problem).
