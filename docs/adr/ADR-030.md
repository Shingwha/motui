# ADR-030 · Control styling is shared roles plus overlays

- **Status:** Accepted (2.1.2)
- **Context:** 2.0's `ControlStyles` carried `base`, `active` and `band()`
  while each widget family merged its own `_band` copy. Buttons had one
  neutral floor; the dialog button's destructive role was a boolean beside
  no other role; input fields and dialogs had no shared floor token. Adding
  button kinds in 2.1 risked turning the theme into a per-component recipe,
  which 2.0 had deliberately rejected.
- **Decision:** The theme stays shared role groups. `SurfaceStyles` gains
  `control` (field and neutral floor), `accent` and `danger` (solid button
  floors) and `inactive` (unfocused cursor band). `ControlStyles` shrinks to
  four state styles -- `hover`, `focus`, `active`, `disabled` -- plus
  `overlay(hovered=, focused=, pressed=, disabled=)` with the precedence
  `disabled > pressed > focused > hovered`. `ButtonKind` has four roles and
  `action_band(kind, theme, ...)` is the one mapping: `NEUTRAL` =
  `surfaces.control` + `text.base`, `PRIMARY` = `surfaces.accent` +
  `text.inverse`, `GHOST` = no floor + `content.accent`, `DANGER` =
  `surfaces.danger` + `text.inverse`. Dialog interior cells sit on
  `surfaces.raised`; Input/Editor rows sit on `surfaces.control`;
  Link/Tabs/MenuBar show focus through the overlay. `Theme.flat()` maps
  every `surfaces.*` token to `NONE` and keeps state legible through
  attributes (`reverse`, `underline`, `dim`).
- **Why:** One merge rule means a new state reads the same everywhere and
  a theme author fills role tokens, not component recipes. `kind` is a
  role, not a boolean, so a fourth or fifth role does not add a second
  flag. The flat theme proves the contract is attribute-based and does not
  depend on color. The 2.0 no-recipe rule survives: tokens are shared
  roles, not per-widget styles.
- **Consequences:** `ControlStyles.base`, `ControlStyles.active` and
  `band()` are removed; every family uses `action_band` or `overlay`.
  A dialog button's destructive role is now `ButtonSpec(kind=ButtonKind.DANGER)`.
  A new floor requires a `SurfaceStyles` token, and `Theme.flat()` must
  cover it. The semantic goldens changed only in SGR, not in row text.
- **Alternatives:** Per-component style recipes (rejected: the 2.0
  no-recipe rule); keep the family `_band` copies (rejected: merge order
  drifts); expose numeric style knobs (rejected: no role vocabulary).
