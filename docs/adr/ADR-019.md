# ADR-019 · add/get/remove return a Section; position is an enum

- **Status:** Accepted (2.0)
- **Context:** The 1.x return types were inconsistent: `App.add` answered
  an id, `App.get` a component, `Document.add` a block. Direction strings
  (`"vertical"`, `"horizontal"`) in `split` read as the opposite of what
  they meant.
- **Decision:** `add`, `get` and `remove` answer a `Section` at every
  level (`App`, `Workspace`, `Document`, `Pane`). Position uses enums:
  `split(Axis.X)` divides width, `split(Axis.Y)` divides height, and
  `dock(placement=Placement.BOTTOM)`. The ratio parameter is `weights`,
  because the values are weights, not fractions.
- **Why:** One return type removes "is this an id or an object?" from every
  call site, and enum directions cannot be misread.
- **Consequences:** Callers keep `section.id`, `section.widget` and the
  placement/sizing. The old direction strings remain accepted as
  documented compatibility entries, but they are not the recommended
  surface.
- **Alternatives:** Keep id/component/block returns (rejected: three
  contracts for one operation); keep string directions (rejected: the
  vertical/horizontal ambiguity is real).
