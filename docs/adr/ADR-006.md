# ADR-006 · Timers schedule by deadline

- **Status:** Accepted (2.0)
- **Context:** The 1.x timer computed `next_run = now + period` after every
  run, so a 50 ms timer drifted to 58-65 ms under load, and tests had to
  sleep to advance animation.
- **Decision:** `next_run` advances by exactly one period. `Runtime.every`
  accepts `catch_up="skip"` or `"coalesce"`, while `Runtime.advance(dt)`
  moves a virtual clock for tests and replays. `animation(hz, draw)` uses
  the same schedule and drops frames it cannot keep up with.
- **Why:** A fixed rate does not drift, a missed deadline has an explicit
  policy, and a test can replay frames deterministically without sleeping.
- **Consequences:** A timer that falls far behind discards or coalesces
  missed runs; it never emits a burst of catch-up frames. The library owns
  no real sleep.
- **Alternatives:** Keep `now + period` (rejected: drift); use real
  `sleep()` (rejected: tests become slow and non-deterministic).
