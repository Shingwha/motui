# ADR-012 · Wrapping is a content policy

- **Status:** Accepted (2.0)
- **Context:** The 1.x tree called `fit` in 59 places, always truncating.
  Code blocks, diffs and wide tables silently lost content, and a single
  global wrap switch would have made the wrong tradeoff for at least one
  of them.
- **Decision:** `WrapMode` (`WORD`, `CHAR`, `ELLIPSIS`, `CLIP`,
  `OVERFLOW`) plus `Line.reflow`/`Line.clip` is the width vocabulary, and
  each content type chooses its default: code blocks and Markdown wrap,
  `Input` stays single-line and follows the cursor, `Table` uses `WORD`
  by default and offers `OVERFLOW` for a horizontal container, `Diff`
  keeps ellipsis so `+`/`-` stay aligned.
- **Why:** Content types have genuinely different needs. A shared
  vocabulary keeps the implementation single while the policy lives at the
  component.
- **Consequences:** The old `fit`-only behavior is no longer the default
  for code blocks, and `Table(wrap=bool)` is gone in favor of
  `cell_wrap=WrapMode` with `OVERFLOW` for the horizontal case.
- **Alternatives:** A global `App(wrap=...)` switch (rejected: one policy
  cannot serve code, tables and diffs).
