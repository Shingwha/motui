# ADR-020 · A command declaration wires itself

- **Status:** Accepted (2.0)
- **Context:** A 1.x `Command` had no `group` field, so the demo put a
  topic group into the description. Its `keys` were never connected to the
  App, and `open_palette` accepted an untyped `list[object]`.
- **Decision:** `Command` is keyword-only with `name`, `description`,
  `group`, `handler`, `keys` and `enabled`. `CommandRegistry.bind(app)`
  connects every key to `invoke(name)`. `App.open_palette(registry)`
  accepts the registry and renders its options.
- **Why:** A declaration and its wiring live in one place. The type is
  explicit, `group` is first-class, and the keyword-only constructor stops
  the "second positional argument is a description" mistake.
- **Consequences:** A disabled command stays registered and bound; invoking
  it is a no-op. The palette also still accepts a plain option list as a
  compatibility entry. Palette grouping is a later UI change: 2.0 renders
  the description.
- **Alternatives:** Keep manual binding (rejected: easy to forget); make
  `open_palette` take a list only (rejected: loses names, keys and
  enablement).
