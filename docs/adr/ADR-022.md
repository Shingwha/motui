# ADR-022 · One-shot results are take()

- **Status:** Accepted (2.0)
- **Context:** The 1.x one-shot door was `take_result()`, which is not a
  standard UI name, and `Resultful` was an awkward protocol name. The
  combination of a pending value and a readable state was also easy to
  misunderstand: a `bool | None` result invites truthiness bugs.
- **Decision:** The door is `take() -> object | None`; the protocol is
  `HasResult`. Reading clears the pending value. `None` means "nothing
  pending"; `False`, `0` and `""` are real results. State attributes
  (`selected`, `checked`, `text`, `open`) remain readable and are not
  cleared by `take()`.
- **Why:** Rust's `Option::take` gives the same short, well-understood
  consumption semantics. One door for one-shot values keeps the API small,
  and `WIDGETS.md` states the `is not None` rule for boolean results.
- **Consequences:** A widget that legitimately returns `None` (a cancel)
  is distinguished by the take itself; a host that needs the current value
  without consuming it reads the state attribute.
- **Alternatives:** Keep `take_result` (rejected: non-standard and long);
  a `result()` getter that clears (rejected: misleading).
