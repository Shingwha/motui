# ADR-005 · kernel has no I/O

- **Status:** Accepted (2.0)
- **Context:** The 1.x `core/` package mixed pure values with about 2,150
  lines of terminal I/O, so the kernel could not be used without a
  terminal, and a server-side or recorded render pulled the console stack
  in with it.
- **Decision:** Bytes, screens, decoders, key sources, capability probes and
  the clipboard live in `motui.terminal`. `motui.kernel` may import the
  standard library and `wcwidth` only; in particular it may not import `os`,
  `sys`, `io`, `ctypes`, `termios`, `tty`, `select` or `asyncio`.
- **Why:** The kernel stays a pure value layer that can render to an
  in-memory screen, a recording or a test. The rule is machine-checked by
  `import-linter`, not left to review.
- **Consequences:** `Screen` is defined in `terminal`, not `kernel`.
  `Theme.auto(env)` takes an explicit mapping; the convenience that reads
  `os.environ` is `terminal.auto_theme()`. Kernel tests need no terminal
  fixture.
- **Alternatives:** Keep everything in `core/` (rejected: the dependency
  graph cannot be enforced); split only documentation (rejected: no
  protection).
