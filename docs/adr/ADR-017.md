# ADR-017 · One concept, one door

- **Status:** Accepted (2.0)
- **Context:** The 1.x tree offered several parallel doors: public
  `ansi.*` alongside `Screen`, `App.add` alongside a driver-level add,
  `EveryHandle` alongside a timer concept. A change that missed one door
  left two behaviors that could drift.
- **Decision:** Each concept has exactly one public door: terminal output
  goes through `Screen`/`Terminal`; timers through `Runtime.every` /
  `animation`; panes and content through `Workspace`; events through the
  documented dispatch order; themes through the widget's resolved group.
  Remove the duplicate doors.
- **Why:** One door is one behavior to test and one place to change. It
  also makes the public surface small enough for `tools/api.py` to pin.
- **Consequences:** `motui.terminal.ansi` is private and not re-exported.
  The timer handle is a `Timer` with `cancel()`/`cancelled`, not a hit-test
  value. `App.add` and `Workspace.add` are the same path, and both answer a
  `Section`.
- **Alternatives:** Keep the duplicate doors (rejected: the source of the
  original drift).
