# W2.6a · ScrollPanel 2D + 水平条 + wheel/hit

> 分支 `2.0/w2.6a-scrollx`；前置：W2.5b 已合并（`44f5121`）；写入范围：`src/motui/widgets/scroll.py`、`src/motui/kernel/layout.py`（thumb 统一）、`src/motui/app/application.py`（wheel 路由）、`tests/widgets/test_scroll.py`、`tests/kernel/test_layout.py`、`tests/app/test_app.py`
> 权威：`ref/source/10-waves/W2.6-horizontal-scroll.md` §1–6、`02-core-contracts.md` §6

## 目标

让 `ScrollPanel` 支持横向与双轴滚动（内容侧 OVERFLOW 生产者留 W2.6b）：

1. `axis="y"|"x"|"both"`；
2. 子组件可返回比约束更宽的 `Surface`；面板按 `x` 偏移硬裁（不加省略号）；
3. `bar=True`：y 画右列、x 画底行、both 画两条；与 y 共用 `ScrollAxis.thumb` 公式；
4. `wheel_left/right` 路由到最近的横向可滚动组件；y 轮不受影响；
5. `child_at` 把 `col + x_offset` 映射回子组件坐标（hit/click 正确）；
6. 非 OVERFLOW 页面字节不变（57 golden / hash 不变）。

**本波结束：x/y 独立 clamp；200 列假组件在 80 列面板可滚到最右；wheel 只作用横向容器；hit 映射正确；全量门禁绿。**

## 前置上下文

- 必读：`ref/repo-map.md` → `ref/interfaces.md` → `handoff/W2.5b.md` → 本工单。
- 基线：`uv sync --locked`；`pytest`（1352 passed）；`golden --check`（57）；`semantic --check`（57）；`framebench` hash `e7ca544b…`。
- 现状：
  - `ScrollPanel` 只支持 `axis="y"`；内部 `_state: ScrollState`（y），`render` 把子组件渲染到 `inner = width - bar`，再按 `state.offset` 切行；每行 `clip(ELLIPSIS, inner)`。
  - `ScrollState.thumb` 与 `ScrollAxis.thumb` 公式相同（W0/W1）。
  - `App._wheel(event)` 在 `application.py:640`：把 `wheel_up/down` 路由给最近 `Scrollable`；`wheel_left/right` 目前不处理。
  - `ScrollPanel.handle` 处理上下键与 `wheel_up/down`；`child_at` 只映射 y。
  - `Wide` 假组件在测试里可以返回任意宽 `Surface`（`Surface.of(rows, natural_width, pad=False)`）。
- 已知坑：
  - `Surface.width` 是**内容宽度**；ScrollPanel 返回的 Surface 宽度应是**可见宽度**（`c.width`），否则容器会以为内容更宽。
  - 横向裁剪必须用 `cut_line(row, x, x+inner_w)`（硬裁），不能用 `clip(ELLIPSIS)`，否则会加 `…` 且宽度语义错。
  - 纵向切行后再横向切；两者的 offset 独立 clamp。
  - `bar=True` 时，y 条占最右 1 列，x 条占最底 1 行；x 条的 track 宽度是 `inner_w`，thumb 用 `ScrollAxis.thumb(inner_w)`。
  - `child_at` 的滚动条列/行属于面板本身，返回 `None`；内容列 = `col + x_offset`，内容行 = `row + y_offset`。
  - wheel 路由不要用 `isinstance(ScrollPanel)`（app 不 import widgets）；用结构化 Protocol（如 `ScrollableX`，方法 `scroll_x_by(delta)->bool`）在 `kernel/layout.py` 或 `kernel/document.py` 定义，`App._wheel` 沿 `hit.chain` 反向找第一个有该方法的对象。
  - `ScrollState.thumb` 改成委托 `ScrollAxis.thumb`，只保留一套公式；测试对照旧数据。
  - 非横向页面（axis y）字节必须不变：`bar` 的现有绘制/裁剪路径保持；只有 x/both 走新分支。
- 不改 Table/Diff/Markdown/Editor 的 OVERFLOW 生产（W2.6b）；用测试假组件验证。

## 工单（按序，每步一个 commit）

### T1 `ScrollState.thumb` 委托 `ScrollAxis.thumb`

- `kernel/layout.py`：`ScrollState.thumb(track,min_length)` 构造 `ScrollAxis(offset=self.offset, content=self.content_height, viewport=self.viewport_height)` 并返回其 `thumb`；行为与旧公式逐值一致。
- 测试 `tests/kernel/test_layout.py`：用 1.x 的 thumb 数据表对照；现有滚动条测试保持绿。
- 只允许改：`kernel/layout.py`、`tests/kernel/test_layout.py`。
- 验证：`uv run pytest -q tests/kernel/test_layout.py tests/app/test_scrollbar.py`。

### T2 `ScrollPanel` 2D

- `widgets/scroll.py`：
  - `axis` 接受 `"y"|"x"|"both"`，其它 `ValueError`。
  - 新增 `_x: ScrollAxis`（offset/content/viewport）；`x_offset`、`total_columns`、`viewport_width` 属性；`scroll_x(delta)` / `scroll_to_x(offset)` / `scroll_x_to_end()`。
  - `render`：
    1. `bar_y = self.bar and axis in ("y","both")`；`bar_x = self.bar and axis in ("x","both")`；
    2. `inner_w = max(0, c.width - (1 if bar_y else 0))`；`inner_h = height - (1 if bar_x else 0)`（height 计算沿用现状：显式 height / c.max_height / 子内容高度）；
    3. `surface = self.child.render(Constraints(width=inner_w))`；`child_rows = list(surface)`；
    4. `content_w = max([surface.width, *(row.width for row in child_rows)], default=0)`；`content_h = len(child_rows)`；
    5. y 状态 `content_height/viewport_height` clamp；x 状态 `ScrollAxis(offset=self._x.offset, content=content_w, viewport=inner_w).clamp()`；
    6. 取 `child_rows[y0:y0+inner_h]`；每行先 `cut_line(row, x0, x0+inner_w)`（x/both），再 `fill(inner_w)`（需要 bar_y 时）；
    7. x 条：底部一行，`thumb = x.thumb(inner_w)`；track 用 `glyphs.bar_empty`/`bar_full`，长度 `inner_w`；y 条：右侧列，逻辑不变；
    8. 返回 `Surface.clipped(out, c.width)`（visible width）。
  - `child_at(row,col)`：bar_y 的最后一列、bar_x 的最后一行返回 `None`；内容坐标 `(row + y_offset, col + x_offset)`。
  - `handle(event)`：`wheel_left/right` 在 axis x/both 时 `scroll_x(±1)` 并在移动时 `True`；`wheel_up/down` 在 axis y/both 时保持现状；x-only 时上下轮返回 `False`。
  - `revision` 加入 `axis`/x 状态（若当前快照含 offset）。
- 测试 `tests/widgets/test_scroll.py`：
  - 假 `Wide` 组件返回 200 列 3 行；`ScrollPanel(axis="x", height=3)` 在 width 20 渲染；`scroll_x(180)` 后最后一行文本含最右内容；`x_offset` clamp 到 `200-20`；
  - `axis="both"`：x/y 独立 clamp；
  - `bar=True` 的 x 底行、y 右列、both 两条；
  - `child_at` 在 x 滚动后映射正确；滚动条行/列返回 None；
  - 非 `OVERFLOW` 旧 y 页面渲染与 W2.5b 相同（可用夹具快照）。
- 只允许改：`widgets/scroll.py`、`tests/widgets/test_scroll.py`。
- 验证：`uv run pytest -q tests/widgets/test_scroll.py`。

### T3 wheel 路由

- `kernel/layout.py`（或 `kernel/document.py`）新增：
  ```python
  class ScrollableX(Protocol):
      def scroll_x_by(self, delta: int) -> bool: ...
  ```
- `app/application.py` `_wheel`：
  - `wheel_left/right`：取 `tui.hit(event.x,event.y)` 的 `chain`，反向找第一个有 `scroll_x_by` 的对象并调用 `scroll_x_by(±1)`；消费则 `invalidate()`；
  - `wheel_up/down`：保持现有 `Scrollable` 路由；若最近对象是 x-only，则继续向外找 y 可滚动者（或按现有逻辑失败）；
  - 不 import widgets；只用结构化 Protocol。
- `ScrollPanel` 增加 `scroll_x_by(delta)`（调 `scroll_x`）。
- 测试 `tests/app/test_app.py`：
  - headless App/TUI 中挂一个 `ScrollPanel(axis="x")` 包住 Wide 组件；
  - 发 `MouseEvent(button="wheel_right", kind="wheel", x=..., y=...)`；x 偏移变化、y 不变；
  - `wheel_down` 不改变 x、仍能滚 pane（若 pane 可滚）。
- 只允许改：`kernel/layout.py` 或 `kernel/document.py`（二选一放 Protocol）、`app/application.py`、`widgets/scroll.py`（只加 `scroll_x_by`）、`tests/app/test_app.py`。
- 验证：`uv run pytest -q tests/app/test_app.py tests/widgets/test_scroll.py`。
