## A. 交付面与门禁

### API / 几何
| 项 | 行为 |
|---|---|
| `axis` | `"y"`（默认）/`"x"`/`"both"`；其它值构造期 `ValueError` |
| `x_offset` / `total_columns` / `viewport_width` | 只读；上一次 render 的 clamp 结果（首帧前为 0） |
| `scroll_to_x` / `scroll_x` / `scroll_x_to_end` | y-only 一律 `False`；首帧前接受目标，首帧 clamp |
| `scroll_x_by(delta)` | `ScrollableX` 结构化面，委托 `scroll_x` |
| `child_at(row,col)` | 内容坐标 `(offset+row, x_offset+col)`；bar 行/列/角返回 `None` |
| `handle` | `wheel_left/right` 只在 x/both 生效；`wheel_up/down` 只在 y/both 生效（x-only 拒收） |
| `revision` | 含 axis 与两个 offset |

- `bar_y = bar and axis in (y,both)` 占最右 1 列，子组件渲染 `width-1`；
  `bar_x = bar and axis in (x,both)` 占最底 1 行，track 宽 `inner_w`。
- `height` 沿用现状：显式 height / `c.max_height` / 子内容行数；x 条画在这个槽内，
  `inner_h = max(0, height - bar_x)`（自然高 + x 条会用掉最后一条内容行）。
- 横向硬裁链：`cut_line(row, x0, x0+inner_w)` → `clip(CLIP, inner_w)`；后者必要：
  `cut_line` 的 start 落在宽簇内部会 floor 到簇首，结果可能比 `inner_w` 多 1 列。
  横向绝无 `…`；y-only 仍是 `clip(ELLIPSIS, inner_w)`，字节不变。
- both 的右下角不属于任一条 track：画 `bar_empty` + `chrome.scrollbar`，视觉上归 y 条。
- x 条 thumb 走 `ScrollAxis.thumb(inner_w)`；`ScrollState.thumb` 已在 T1 委托
  `ScrollAxis.thumb`（一套公式；1.x 数据表 10 例 + 既有随机 1000 例对照通过）。
- `Surface.width` 恒为可见宽 `c.width`；内容宽只存 `total_columns`，容器不会误判可滚。

### wheel / hit
- `ScrollableX` 在 `kernel/layout.py`：`scroll_x_by(delta) -> bool`。
- `App._wheel`：`wheel_left/right` 沿 `hit.chain` 反向找第一个 `ScrollableX`，
  **实际移动才消费**并 `refresh()`；未移动（x 到边界 / y-only 的结构性方法返回
  False）继续向外找。`wheel_up/down` 完全保持原 `Scrollable` 路由（1.x 语义）。
- `app` 不 import widgets；`lint-imports` 4 kept。
- `child_at` 在 x/both 额外拒绝 `x_offset+col >= total_columns`（空白填充列不归子组件）；
  y-only 不加该检查，保持旧行为。
- bar 行/列在 `descend_chain` 处即终止，子组件收不到；`click` 消费 x 条行。

## B. 实现细节 / 坑 / W2.6b 接线

1. **高度语义**。x-only 仍沿用 height 的纵向 window：显式 height 会裁内容行；
   要看全部行用 `height=None`。`viewport_height` 现在扣除 x 条行（y-only 不变）。
2. **首帧前 x 目标**。`scroll_to_x` 在 `_rendered=False` 时只做下界 clamp，首帧
   `ScrollAxis.clamp` 再按真实 content 收敛；与纵向的 `_rendered` 规则一致。
3. **宽簇边界**。实测 `cut_line("界abcdefghijk", 1, 11)` 宽 11；`clip(CLIP)` 是
   必要的第二道门，且不会引入 `…`。
4. **横向“移动才消费”** 与纵向“找到即消费”不同；W2.6b 若需要内层到边界后外滚，
   横向已就绪；纵向保持 1.x 语义未动。
5. **W2.6b 接线清单**（OVERFLOW 生产者，本波未动）：`Markdown` 代码行（W2.5b
   仍被自身 `Surface.clipped(c.width)` 裁）、`Table`、`Diff`、`Editor`。让它们在
   `c.width` 下返回自然宽 `Surface`（`Surface.of(..., pad=False)`）即可被
   `ScrollPanel(axis="x"|"both")` 横向滚动；ScrollPanel 无需再改。
6. **Demo**。`demo/topics/{interactions,components_layout}.py` 的 `ScrollView` 都是
   默认 axis / 无 bar，字节与 W2.5b 相同；demo 未改。
7. **未做**（工单未要求）：x 条拖拽 / 轨道点击翻页、键盘 left/right、`Scroll`
   聚合值接入 ScrollPanel；纵向拖拽逻辑保持不变。
8. **测试位置**。`tests/kernel/test_hit.py` 不存在，T4 的 hit 测试落在
   `tests/widgets/test_scroll.py`（`descend_chain` + `RecordingLeaf`）。
