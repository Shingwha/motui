## 目标

只改两处默认（其余保持 W2.5a 的字节）：

1. **Markdown 代码块**：`code_wrap=WrapMode.WORD` 默认，长行完整换行可读（可选 `ELLIPSIS/OVERFLOW`）；
2. **Input**：`wrap=WrapMode.OVERFLOW` 默认，恒一行；宽文本按光标水平跟随（不换行、不丢尾）；
3. 重录 57 字节 golden + 57 语义 golden，并给出**差异分类报告**（只允许“代码块 / Input”两类）；
4. 新增代码块长行、Input 200 字符一行、光标水平跟随的测试。

**本波结束：全量 pytest 绿；byte/semantic golden 已重录并 `--check` 通过；差异分类只含代码块与 Input；Input 恒一行；代码块长行可读。**

## 前置上下文

- 必读：`ref/repo-map.md` → `ref/interfaces.md` → `handoff/W2.5a-wrap.md` → 本工单。
- 基线：`uv sync --locked`；`pytest`（1337 passed）；`golden --check`（57）；`semantic --check`（57）；`framebench` hash a82f7968…。
- 现状：
  - `_TextField.__init__(wrap=WrapMode.ELLIPSIS)`；`Input.__init__` 没传 wrap（用 ELLIPSIS）；`Editor` 默认 WORD。`_rows_for` 用 `_buf.visual_rows(width, indent)` + `_window` + `row_body`，行超宽时按 `_wrap` 走 `reflow`/`clip`。
  - `Input` 有 `prompt`、`_indent()`、`_row_prefix()`、`_mask`、`cursor`（row=0, col=offset）；`_buf.offset` 是字符偏移。
  - `TextBuffer.row_body(text, column, inner, base, caret, ..., show_cursor=...)`：`column` 是字符索引；行尾且 `visible_width(text)+1 <= inner` 时追加 reverse 空格；否则把光标字符改样式。
  - `kernel.text.index_pair_at_columns(text, first, second)` 把显示列区间映射成字符索引；`visible_width` 是显示宽。
  - Markdown：`RenderContext`（frozen）由 `Markdown.__init__` 构造；`FenceRule.render` 在 `markdown/blocks.py`，当前 `row.clip(ELLIPSIS,width)`；`Markdown.revision` 包含 `_ctx` 的字段（读代码确认）。
  - `Markdown.__init__` 参数：`text, block_rules, inline_rules, theme, styles, highlighter, glyphs, gap, divider_max_width, max_width`；`_ctx = RenderContext(...)`。
- 已知坑：
  - Input 的 `text` 可能含 `\n`（显式 `insert("\n")`）；单行显示要把 `\r\n`/`\n` 折成一个空格（与 paste 规则一致），字符偏移保持 1:1（替换，不删除），否则光标错位。
  - `mask` 是“每个字符替换为 mask 的首字符”；单行显示按 masked 字符串算宽度；光标字符索引仍是原 offset。
  - 光标在末尾、文本填满 `inner` 时，`row_body` 不会追加空格；选择 `scroll_x` 要让光标落在可见窗口的最后一列（`cursor_col - inner + 1`），这样 `row_body` 能把最后一个字符染成光标。
  - `Input` 的 prompt 宽度 >= width 时，只显示裁掉的 prompt，不显示文本；不要抛错。
  - 代码块换行必须保留 highlighter 的 segment 样式；用 `row.reflow(WORD,width)`，不要纯文本重建。
  - Markdown 的 stream cache 键目前是 `(text, width)`；`code_wrap` 变化必须 miss（把 code_wrap 加入 cache key 或 revision 并清缓存）。
  - `Surface.clipped` 会裁掉 OVERFLOW 宽行；本波 `code_wrap=OVERFLOW` 的端到端自然宽留给 W2.6，组件层只保证参数可构造、ELLIPSIS/WORD 行为正确。
  - golden 重录会改变多个 topic；必须逐 topic 分类，不能把非代码块/Input 的变化混进去。
- 不改 Editor 的默认（仍是 WORD）；不改 Table/Diff 的默认（W2.5a 已定）。

## 工单（按序，每步一个 commit）

### T1 Markdown `code_wrap`

- `widgets/markdown/context.py`：`RenderContext` 增加 `code_wrap: WrapMode = WrapMode.WORD`（frozen 字段；`WrapMode` 从 `...kernel.text` import）。
- `widgets/markdown/blocks.py` `FenceRule.render`：
  - 围栏行（```lang / ```）保持 `ELLIPSIS` 裁剪；
  - 代码行：`row.reflow(ctx.code_wrap, width)`（WORD 默认逐行换行；ELLIPSIS/CLIP 单行；OVERFLOW 原样）。
- `widgets/markdown/component.py`：
  - `Markdown.__init__` 增加 `code_wrap: WrapMode = WrapMode.WORD`；
  - `RenderContext` 构造传 `code_wrap`；
  - `Markdown.code_wrap` 作为可写属性（setter 更新 `_ctx` 并清 stream cache），或至少参与 `revision` 与 `_sync_theme`；
  - `revision()` 包含 `code_wrap`；`_StreamCache` 键/`_stamp_key` 加 `code_wrap`（读现有实现决定最稳的键）。
- 测试 `tests/widgets/test_markdown.py`：
  - 200 字符代码行 + `width=40` + 默认 → 多行拼接含完整代码（无 `…`）；
  - `code_wrap=ELLIPSIS` → 单行含 `…`；
  - highlighter 的自定义颜色跨换行保留（用简单断言检查 segment 样式）。
- 只允许改：`widgets/markdown/{context,blocks,component}.py`、`tests/widgets/test_markdown.py`。
- 验证：`uv run pytest -q tests/widgets/test_markdown.py`。

### T2 Input `OVERFLOW` 单行水平跟随

- `widgets/textfield.py`：
  - `Input.__init__` 增加 `wrap: WrapMode = WrapMode.OVERFLOW`，透传 `super().__init__(..., wrap=wrap)`；加 `wrap` 属性（getter/setter，setter 清 memo）。
  - 在 `Input` 覆写 `_rows_for(self, width)`：
    - `if self._wrap is not WrapMode.OVERFLOW: return super()._rows_for(width)`；
    - `inner = max(0, width - indent)`；`indent >= width` → 只返回裁到 width 的 prompt 行；
    - 显示文本：`raw = self._buf.value.replace("\r\n"," ").replace("\r"," ").replace("\n"," ")`；若 `_mask` 非空，`display = self._mask[0] * len(raw)`，否则 `display = raw`；
    - `cursor_offset = self._buf.offset`（字符偏移；替换换行不改长度）；
    - `cursor_col = visible_width(display[:cursor_offset])`；
    - `scroll_x = 0`；若 `cursor_col < scroll_x` → `cursor_col`；若 `cursor_col >= scroll_x + inner` → `cursor_col - inner + 1`；
    - `start_idx, end_idx = index_pair_at_columns(display, scroll_x, scroll_x + inner)`；`visible = display[start_idx:end_idx]`；`local = max(0, min(len(visible), cursor_offset - start_idx))`；
    - placeholder（空 + focused）走原来的 hint 路径（无光标）；
    - `body = self._buf.row_body(visible, local, inner, text.base, text.caret, show_cursor=self.focused)`；
    - `line = Line((prompt_segment, *body))`；hover 时合并 `surfaces.hover`（与 `_TextField._rows_for` 相同）；
    - 返回 `[line.clip(WrapMode.CLIP, width)]`（保证 ≤ width）。
  - `_revision` 已含 `_wrap`；确认 memo 会因 `wrap` 改变而 miss。
- 测试 `tests/widgets/test_editing.py`：
  - 200 字符 Input 在 width 20/40 下始终 1 行；
  - 光标在末尾时可见（渲染文本以最后几个字符结尾，光标样式在最后可见格）；
  - `home`/`left` 后窗口回到开头；`end` 后回到尾部；
  - 空 + focused 的 placeholder 仍是 1 行无光标；
  - mask 非空时仍 1 行、光标位置正确；
  - prompt 宽度 >= width 时不抛错、只显示 prompt。
- 只允许改：`widgets/textfield.py`、`tests/widgets/test_editing.py`。
- 验证：`uv run pytest -q tests/widgets/test_editing.py`。
